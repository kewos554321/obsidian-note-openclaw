## 台灣房市觀察（2026-11-25）

**1. 整體趨勢**
央行選擇性信用管制與高利率環境持續壓抑交易量，市場呈「量縮價盤整」格局；高總價住宅成交單價仍見每坪百萬以上（如 449,312 元/㎡ ≈ 148.6 萬/坪），但去化期拉長，買方議價空間明顯擴大，賣方讓利意願上升。

**2. 值得注意的地區／物件**
- **南港車站三鐵共構商圈**：企業租辦需求穩定，商辦、店辦掛牌密集，是商用不動產的抗跌區塊。
- **中山區（松江南京、行天宮、中山國中）**：捷運雙線交會、含車位店辦與住宅需求並存，租賃市場支撐性強。
- **內湖科學園區周邊**：挑高 6 米廠辦、店辦稀有釋出，適合自用型企業進場。
- **淡水竹圍捷運宅**：單價相對親民、生活機能成熟，屬自住剛需可留意區。

**3. 對自住者建議**
優先鎖定捷運站 500 公尺內、含車位的中小坪數產品，利用目前議價空間大的時機，從實價登錄近期成交價往下 5–10% 出價；避開供給量大的重劃區預售案。

**4. 對投資者建議**
住宅投報率受高利率侵蝕，建議轉向**商用店辦、廠辦**（南港、內湖、中山）等有企業剛需支撐的標的；高總價住宅（近 3 億級）流動性差，不宜短線進出。

**5. 風險提醒**
留意 2027 年若信用管制鬆綁前的政策變數，以及高總價物件（單價 45 萬/㎡ 以上）議價週期拉長、轉手不易的流動性風險。

#### 📚 Today's Concept: Debt-to-Equity Ratio

What it is: The Debt-to-Equity (D/E) ratio measures how much a company relies on borrowed money versus shareholder money, calculated as total liabilities divided by shareholders' equity. It's a leverage gauge: a D/E of 1.0 means creditors and owners each fund half the company.

Why it matters: It tells you how much financial risk a company carries—high leverage amplifies both profits and losses, and can force a company into distress if cash flow drops. Use it to compare companies within the same industry before buying a stock.

Example: Company A has $400M in total liabilities and $200M in shareholders' equity, so D/E = 400/200 = 2.0. Company B has $150M liabilities and $300M equity, so D/E = 0.5. Company A is twice as leveraged relative to its equity base—riskier if revenue falls.

Rule of thumb: Compare D/E only within the same industry (utilities and banks run high; tech often runs low), and treat a D/E above 2.0 as a warning sign unless the business has stable, predictable cash flows.

#### 🧩 Blind 100 — 704. Binary Search [Binary Search]
**連結:** https://leetcode.com/problems/binary-search/
> 📅 **Today's Daily Challenge:** #4105 Smallest Unique Subarray [Hard] — Tags: Array, Hash Table, Binary Search, Rolling Hash, Suffix Array, Hash Function — https://leetcode.com/problems/smallest-unique-subarray/

**Problem Type:** Binary Search (classic search in sorted array)

**Key Insight:** Maintain a `[lo, hi]` window of *candidates*. Compare `nums[mid]` to `target` and discard half each iteration. Use `lo <= hi` for inclusive bounds, or `lo < hi` with `hi = mid` for the "find boundary" variant.

**Approach:**
1. Initialize `lo, hi = 0, len(nums) - 1`.
2. Loop while `lo <= hi`.
3. Compute `mid = (lo + hi) // 2` (Python ints don't overflow, so no need for `lo + (hi-lo)//2`).
4. If `nums[mid] == target`, return `mid`.
5. If `nums[mid] < target`, `lo = mid + 1`; else `hi = mid - 1`.
6. Return `-1` if loop exits.

**Python3 Solution:**
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[mid] < target:
                lo = mid + 1
            else:
                hi = mid - 1
        return -1
```

**Complexity:** Time O(log n) | Space O(1)

**Blind 100 Note:** This is the canonical binary search template — the foundation for ~15 NeetCode problems (Search in Rotated Sorted Array, Find Minimum in Rotated Sorted Array, Koko Eating Bananas, Median of Two Sorted Arrays, Search a 2D Matrix, First/Last Position of Element). Master the *inclusive* template here, then learn the *boundary* template (`lo < hi`, `hi = mid`) for "find first true" problems. Practice: 35, 33, 153, 875, 34, 74.

**Contest Tips:**
- **Edge cases:** empty array (LeetCode guarantees non-empty here, but check in general), single element, target smaller than `nums[0]` or larger than `nums[-1]` (loop naturally handles both).
- **Off-by-one killer:** `lo <= hi` pairs with `lo = mid + 1` / `hi = mid - 1`. Mixing `lo < hi` with `hi = mid - 1` causes infinite loops or missed elements. Pick one template and stick to it.
- **Python trick:** `bisect.bisect_left(nums, target)` gives the insertion index in C-speed — use it in contests when you just need the index and don't need to hand-roll (verify `nums[i] == target` after).
- **Common mistake:** returning `mid` from inside the `if nums[mid] < target` branch, or forgetting the final `return -1`.
- **Contest speed:** This is a 2-minute problem. If you're spending longer, you're second-guessing the template — drill it until it's muscle memory.

#### 📷 Today's Concept: Special — Film Photography Aesthetic and Grain Simulation

**What it is:** Film photography aesthetic is the intentional recreation of analog film's color response, tonal roll-off, and organic grain structure in digital images. Grain simulation adds controlled luminance noise that mimics silver halide crystals, breaking up digital sterility.

**Why it matters:** Grain adds texture, perceived sharpness, and emotional warmth—it makes digital files feel tactile and less "computational." The right grain and color palette instantly evoke nostalgia and cinematic mood.

**How to apply it:**
1. Shoot at moderate ISO (400–1600) to capture *real* sensor noise rather than adding it all in post—organic grain looks more authentic than synthetic.
2. Slightly overexpose (ETTR) and pull back highlights in editing to mimic film's highlight roll-off and latitude.
3. Apply a film-inspired color grade: lifted blacks, muted highlights, and warm-shifted skin tones.
4. Add grain in post (Lightroom/Dehancer) at a size matching your output resolution—grain should be visible at 100% but subtle at fit-to-screen.
5. Reduce digital sharpening and clarity slightly; film isn't clinically sharp.

**Sony A7C tip:** Enable "Picture Profile PP6" (Cine2) or shoot RAW and use Creative Look "FL" for a filmic starting point. Pair with the FE 35mm f/1.8 for a classic documentary field of view.

**Common mistake:** Overdoing grain—heavy synthetic grain looks like noise, not film. Match grain intensity to your final output size and keep it subtle.

#### 📚 Today's Concept: Observability: Metrics, Logs, Traces

**What it is:** Observability is the ability to understand a system's internal state from its external outputs—metrics (aggregated numbers over time), logs (discrete timestamped events), and traces (request paths across services). Together they answer "is it healthy?", "what happened?", and "where did it slow down?"

**When to use it:** Use all three in production distributed systems where failures span services. E.g., a checkout API returns 500s: metrics show the error rate spiking, traces reveal the payment service is the slow hop, and logs pinpoint the exact exception.

**Example:**
```python
# metrics: counter + histogram
orders_failed.inc()
latency.observe(elapsed)

# log: structured event
logger.info("order_failed", order_id=oid, reason="timeout")

# trace: span around the call
with tracer.start_span("charge_card"):
    charge()
```

**Gotcha:** Metrics are cheap to store but lossy (aggregates, no per-request detail); logs are detailed but expensive at scale; traces sample. Don't rely on one—and don't log everything at INFO or you'll drown in cost and noise. Correlate them with a shared trace/request ID.

#### 🎬 今日主題：攝影Vlog — 如何用 Sony A7C 拍出 Cinematic Vlog 感

**是什麼：** Cinematic Vlog 是用電影感的畫面語言（淺景深、穩定運鏡、調色）拍日常，讓 Vlog 看起來像短片。Sony A7C 全片幅感光元件與翻轉螢幕，天生適合這種風格。

**怎麼做：**
