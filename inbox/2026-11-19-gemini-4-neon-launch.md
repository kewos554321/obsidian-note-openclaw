## 台灣房市速報（2026-11-19）

**1. 整體趨勢**
房市呈「量縮價撐、區域分化」格局：高總價住宅仍有成交但去化放緩，蛋黃區單價站穩高檔（實價登錄見每坪約90–150萬的豪宅級成交），蛋白區靠新青安與低總價產品撐盤，租賃市場因購屋門檻高而需求強勁。

**2. 值得注意的地區／物件**
- **桃園大園客運園區**：新青安首購熱區，一層兩戶、含車位三房，屬低總價剛需產品，留意航空城與客運園區供給量。
- **苗栗竹南**：科學園區外溢效應，孝親別墅型產品吸引竹科換屋族。
- **台北市蛋黃區租賃**（內湖、大安、大同）：捷運＋機能物件租金支撐強，適合收租型布局。
- **台中中區、太平**：火車站周邊與學區套房，總價低、投報率相對佳但管理成本高。

**3. 對自住者建議**
優先鎖定新青安適用、含車位、近軌道的低總價成屋；蛋白區（大園、竹南）可議價空間較大，但務必確認區域供給與未來轉手性，避免追高預售。

**4. 對投資者建議**
高總價豪宅成交單價雖高但流動性差，不宜短線；建議聚焦「捷運蛋黃區小宅收租」與「產業園區外溢低總價」兩類，並以租金投報率＞2.5%、空置率低為篩選門檻。

**5. 風險提醒**
實價登錄高總價樣本偏豪宅，不代表全區行情；信用管制與新青安政策變動、蛋白區餘屋去化壓力，是2027年前主要觀察點。

#### 📚 Today's Concept: Enterprise Value (EV) and EV/EBITDA

What it is: Enterprise Value is the total price you'd pay to buy the whole business outright — market cap plus debt minus cash — because acquiring the company means inheriting its obligations and its cash. EV/EBITDA divides that total price by EBITDA (earnings before interest, taxes, depreciation, and amortization), giving a debt-neutral, tax-neutral multiple of operating profit.

Why it matters: It lets you compare companies with wildly different capital structures and tax situations on equal footing, which plain P/E cannot do. It's the standard lens for valuing acquisition targets and capital-intensive businesses.

Example: Company A: market cap $500M, debt $200M, cash $50M. EV = 500 + 200 − 50 = $650M. EBITDA is $65M, so EV/EBITDA = 10x. Company B trades at 10x too, but carries heavy debt — same EV multiple means the market prices their operating engines identically, regardless of leverage.

Rule of thumb: Treat EV/EBITDA above roughly 10-12x as expensive unless growth justifies it, and beware: EBITDA ignores real costs like capex and interest, so a low multiple on a capital-hungry business is often a trap, not a bargain.

#### 🧩 Blind 100 — 33. Search in Rotated Sorted Array [Binary Search]
**連結:** https://leetcode.com/problems/search-in-rotated-sorted-array/
> 📅 **Today's Daily Challenge:** #2706 Minimum Score by Changing Two Elements [Medium] — Tags: Array, Greedy, Sorting — https://leetcode.com/problems/minimum-score-by-changing-two-elements/

## **Problem Type:** Modified Binary Search (rotated array)

**Key Insight:** In a rotated sorted array, at least one half (left or right of `mid`) is always sorted. Determine which half is sorted, check if the target lies within that sorted range, and discard the other half.

**Approach:**
1. Standard binary search with `lo`, `hi`.
2. Compute `mid`. If `nums[mid] == target`, return `mid`.
3. Check if left half `nums[lo..mid]` is sorted (`nums[lo] <= nums[mid]`):
   - If target is in `[nums[lo], nums[mid])`, search left; else search right.
4. Otherwise right half is sorted:
   - If target is in `(nums[mid], nums[hi]]`, search right; else search left.
5. Return `-1` if not found.

**Python3 Solution:**
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[lo] <= nums[mid]:  # left half sorted
                if nums[lo] <= target < nums[mid]:
                    hi = mid - 1
                else:
                    lo = mid + 1
            else:  # right half sorted
                if nums[mid] < target <= nums[hi]:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return -1
```

**Complexity:** Time O(log n) | Space O(1)

**Blind 100 Note:** Classic "modified binary search" pattern — teaches you to preserve the binary-search invariant when the array isn't fully sorted. The same "find the sorted half" trick powers **Find Minimum in Rotated Sorted Array (153)**, **Search in Rotated Sorted Array II (81, with duplicates)**, and **Find Minimum in Rotated Sorted Array II (154)**. Also foundational for **Median of Two Sorted Arrays (4)**.

**Contest Tips:**
- **Use `<=` on the sorted-half check** (`nums[lo] <= nums[mid]`), not `<`. With duplicates or a 2-element array, strict `<` breaks.
- **Boundary comparisons matter:** use `nums[lo] <= target < nums[mid]` (strict upper) — target can't equal `nums[mid]` (already checked).
- **Edge cases:** single element, target at index 0 or n-1, array not rotated at all (still works), target absent.
- **Python trick:** `mid = (lo + hi) // 2` is fine; no overflow concern in Python. Avoid `math.ceil` — stick with floor.
- **Common mistake:** forgetting the `nums[lo] <= nums[mid]` case handles the *non-rotated* subarray too — don't add a separate branch for "not rotated."
- **Follow-up (81):** with duplicates, worst case degrades to O(n) — handle `nums[lo] == nums[mid] == nums[hi]` by shrinking both ends.

#### 📷 Today's Concept: Portrait — Skin Tone Rendering and White Balance

**What it is:** Skin tone rendering is how your camera translates the color of human skin under different light sources, controlled primarily by white balance. It's the difference between skin looking natural and healthy versus orange, green, or washed out.

**Why it matters:** Skin is the emotional anchor of a portrait—viewers instantly notice when it looks "off," even if they can't say why. Nailing white balance makes skin look believable and flattering, which is the foundation every other portrait decision builds on.

**How to apply it:**
1. Set white balance manually or use a custom Kelvin value rather than trusting Auto—lock it in before you shoot a series.
2. Shoot a gray card or white reference in the same light, then use it to set WB in-camera or correct in post.
3. For skin, aim slightly warm—most people look best a touch warmer than technically neutral; avoid pushing too cool, which reads as lifeless.
4. Match WB to your light source: shade runs cool/blue, golden hour runs warm—compensate deliberately.
5. Check skin on a calibrated screen, not the camera LCD, before judging color.

**Sony A7C tip:** Use Custom White Balance (menu: White Balance → Custom) with a gray card, and save it to a memory recall for recurring lighting setups. For portraits, the Sony 55mm f/1.8 or 85mm f/1.8 gives clean, flattering skin rendering.

**Common mistake:** Leaving WB on Auto across changing light—it drifts shot to shot, making skin inconsistent and hard to match in editing. Lock it manually and shoot a reference frame.

#### 📚 Today's Concept: Kubernetes Pod Scheduling

**What it is:** Pod scheduling is the process where the Kubernetes scheduler assigns unscheduled pods to nodes based on resource requests, constraints, affinity rules, and taints/tolerations. It runs continuously, watching for pods with no `nodeName` set and binding them to the best-fit node.

**When to use it:** Use scheduling controls when you need to control placement—e.g., pinning GPU workloads to GPU nodes via node affinity, spreading replicas across zones for HA, or keeping noisy neighbors apart with pod anti-affinity.

**Example:**
```yaml
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: disktype
            operator: In
            values: ["ssd"]
```

**Gotcha:** Setting `resources.requests` too high (or omitting them) causes pods to stay `Pending`—the scheduler can't find a node with enough allocatable capacity. Requests, not limits, drive scheduling decisions.

2. 當晚回飯店用 CapCut 的「自動剪輯」或「文字成片」功能，丟入素材讓 AI 生成初版。
3. 手動微調：刪掉晃動片段、加字幕（AI 自動上字幕）、配一首熱門音樂。
4. 用統一封面模板與開頭 3 秒 hook（例如「今天在XX發現…」）。
5. 直接上傳 Shorts／Reels，並在隔天影片中引流。

**新手常犯的錯：** 想把旅途所有片段都塞進一支影片，導致節奏拖沓。避免方式：一支短影片只講「一個重點」，其餘素材留給長片。

**延伸 idea：** 拍一支「用 A7C 拍旅遊短影片，當晚 AI 剪完直接發」的幕後流程影片，同時展示相機設定與 AI 工具操作，結合攝影＋旅遊＋科技三個方向。
