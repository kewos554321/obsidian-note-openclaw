### 🏠 台灣房市
> `2026-10-10 10:32:46`

#### AI 分析
**1. 整體趨勢（2026年10月）**
央行選擇性信用管制持續、房貸利率仍偏高，市場呈「量縮價撐」格局；自住剛需為主力，投資買盤明顯退場。高總價產品靠資產族群與都更危老支撐，中小坪數、低總價產品去化較快，區域表現分歧擴大。

**2. 值得注意的地區／物件**
- **高總價蛋黃區**：實價登錄多筆單價破 40 萬/㎡（約 130 萬/坪），集中在北市、新北精華區與竹北，顯示資金仍追逐稀缺地段。
- **新竹（竹北、竹東、新埔）**：竹科就業支撐，竹北外溢到新埔、竹東，店面與三房產品詢問度高。
- **台中（西屯、北區、西區）**：科博館、中國醫、中山國中等學區宅租賃與自住需求穩定，低總價 2+1 房為熱門標的。
- **高雄左營**：桃子園、美術館周邊低自備 2 房，吸引首購與換屋族。
- **林口**：國宅、住一建地稀有釋出，長期保值性佳但短期供給量大。

**3. 對自住者的建議**
- 優先選「就業＋學區＋交通」三合一區位（竹北、台中北區、左營），議價空間比去年大，可談 5–10%。
- 避開供給量大的重劃區，交屋潮恐壓抑房價；自備款抓 3 成以上較安全。

**4. 對投資者的建議**
- 高總價產品租金投報率普遍低於 2%，不建議短線進場；若布局，以都更、危老題材的蛋黃區老宅為宜。
- 收租型可看台中學區、竹東市區店面，但須留意空置率與管理成本。

**5. 風險提醒**
- 利率若再升、信用管制未鬆綁，2027 年前房價恐呈「高檔盤整、個案修正」；勿追高、勿過度槓桿。

#### 📚 Today's Concept: Price-to-Earnings (P/E) Ratio

What it is: The P/E ratio divides a company's stock price by its earnings per share (EPS), telling you how much investors pay for each dollar of profit. It's the market's shorthand for how expensive a stock is relative to what the business actually earns.

Why it matters: It lets you compare valuations across companies and against a stock's own history, so you can judge whether you're overpaying for growth or spotting a bargain.

Example: A stock trades at $150 and earned $5 per share last year, so its P/E is 150 / 5 = 30. If a competitor trades at $60 with $5 EPS, its P/E is 12. You're paying 2.5x more per dollar of earnings for the first company, which only makes sense if it's growing much faster.

Rule of thumb: A high P/E isn't automatically bad, but it means the market expects strong future growth, so any slowdown can crush the price. Compare P/E only within the same industry, and always check whether earnings are inflated by one-time gains.

#### 🧩 Blind 100 — 79. Word Search [Backtracking]
**連結:** https://leetcode.com/problems/word-search/
> 📅 **Today's Daily Challenge:** #2418 Minimum Sum of Squared Difference [Medium] — Tags: Array, Binary Search, Greedy, Sorting, Heap (Priority Queue) — https://leetcode.com/problems/minimum-sum-of-squared-difference/

# 79. Word Search

**Problem Type:** Backtracking / DFS on Grid (with in-place visited marking)

**Key Insight:** For each cell matching `word[0]`, DFS in 4 directions matching the next character. Mark the current cell as visited *in-place* (e.g., `board[r][c] = '#'`) and restore it on backtrack — this avoids a separate `visited` set and keeps memory O(1) extra.

**Approach:**
1. Get `R, C = len(board), len(board[0])`.
2. Define `dfs(r, c, i)` returning True if `word[i:]` can be matched starting at `(r, c)`.
3. Base case: `i == len(word)` → True.
4. Bounds check + `board[r][c] != word[i]` → False.
5. Save `tmp = board[r][c]`, set `board[r][c] = '#'`, recurse in 4 directions with `i+1`.
6. Restore `board[r][c] = tmp`, return whether any direction succeeded.
7. Loop over all cells; return True on first success.

**Python3 Solution:**
```python
class Solution:
    def exist(self, board: list[list[str]], word: str) -> bool:
        R, C = len(board), len(board[0])
        n = len(word)

        def dfs(r: int, c: int, i: int) -> bool:
            if i == n:
                return True
            if r < 0 or r >= R or c < 0 or c >= C or board[r][c] != word[i]:
                return False
            tmp = board[r][c]
            board[r][c] = '#'  # mark visited
            found = (dfs(r + 1, c, i + 1) or
                     dfs(r - 1, c, i + 1) or
                     dfs(r, c + 1, i + 1) or
                     dfs(r, c - 1, i + 1))
            board[r][c] = tmp  # backtrack
            return found

        for r in range(R):
            for c in range(C):
                if dfs(r, c, 0):
                    return True
        return False
```

**Complexity:** Time O(R·C·4^L) where L = len(word) | Space O(L) recursion depth (board mutated in-place, no extra visited set).

**Blind 100 Note:** Classic **backtracking on a grid** — the canonical "mark, recurse, unmark" template. Represents the pattern of exploring all paths with pruning and state restoration. Related: Word Search II (212, adds Trie), Number of Islands (200), Path Sum (112), N-Queens (51), Sudoku Solver (37).

**Contest Tips:**
- **Prune early:** If `len(word) > R*C`, return False immediately.
- **Character count check:** `Counter(word) - Counter(flatten(board))` non-empty → False. Big speedup on adversarial cases.
- **Reverse trick:** If `word` starts with a rare char, search from the end (`word[::-1]`) — same answer, fewer starting cells.
- **Don't use a `visited` set** — in-place marking is faster and cleaner in Python.
- **Common bug:** Forgetting to restore `board[r][c]` on the failure path — must restore *before* returning.
- **Recursion limit:** Fine for L ≤ ~1000, but for very long words consider iterative DFS.

#### 📷 Today's Concept: Street — Layering and Depth in Street Compositions

**What it is:** Layering means building a frame with distinct foreground, midground, and background elements that overlap. Depth uses those layers plus leading lines, scale, and selective focus to pull the eye through the scene.

**Why it matters:** Flat street shots feel like snapshots; layered ones feel cinematic. Overlapping subjects create tension, context, and a sense of "peeking into" a moment.

**How to apply it:**
1. Find a static foreground anchor — a doorway, pole, or window frame — and shoot *through* it.
2. Position yourself so a midground subject (person walking) crosses between that anchor and the background.
3. Wait for the decisive overlap: subject not blocking the anchor, background still readable.
4. Use a longer focal length (50–85mm) to compress layers together.
5. Shoot wide open or f/2.8 to soften the nearest layer, keeping the midground sharp.

**Sony A7C tip:** Assign Eye AF to a custom button and enable AF-C with Tracking. On the A7C's smaller body, use the flip-out screen at waist level to shoot discreetly while keeping your layers composed.

**Common mistake:** Cluttering the frame with too many competing elements. Fix it by asking: "What's my foreground, what's my subject, what's the backdrop?" If you can't answer in one second, simplify — remove one layer.

#### 📚 Today's Concept: Vector Databases and Embeddings

**What it is:** A vector database stores data as high-dimensional vectors (embeddings) produced by ML models, enabling similarity search by distance rather than exact matches. Embeddings map semantic meaning into numbers, so "dog" and "puppy" end up close together.

**When to use it:** Use it for semantic search, recommendations, RAG, or deduplication—anywhere "find similar" beats "find exact." E.g., a support bot retrieving relevant docs by meaning, not keywords.

**Example:**
```python
# Embed a query, find nearest neighbors
results = index.query(
    vector=embed("How do I reset my password?"),
    top_k=3,
    include_metadata=True
)
# -> [{"text": "Password reset steps...", "score": 0.91}, ...]
```

**Gotcha:** Embeddings are model-specific—vectors from different models aren't comparable, and mixing them silently breaks search. Also, cosine similarity ≠ correctness: a high score means "similar," not "relevant." Always re-rank or filter with metadata for production quality.

#### 🎬 今日主題：Filmora — 轉場效果的選擇與克制使用原則
**類別：** Filmora

**是什麼：** Filmora 內建大量轉場特效，從基本淡入淡出到動態滑動都有。轉場是兩個鏡頭之間的過渡方式，用來讓剪接點更順暢或製造節奏感。

**為什麼重要：** 轉場用得好能提升觀看流暢度，用太多則會讓影片顯得業餘、廉價，觀眾容易出戲甚至關掉。

**怎麼做：**
1. 先剪好所有片段，最後才加轉場，不要一邊剪一邊加。
2. 全片只選 1-2 種轉場風格（如淡入淡出＋偶爾滑動），維持一致調性。
3. 優先用「硬切」——多數情況直接切換最自然，轉場只在場景或時間跳躍時用。
4. 轉場時長設 0.3-0.5 秒，預設的 1 秒太長會拖節奏。
5. 對照參考頻道，觀察他們多久用一次轉場，模仿其克制程度。

**新手常犯的錯：** 每個剪接點都加炫炮轉場（如翻頁、粒子），以為越華麗越專業。避免方法：先全部硬切，只在你覺得「這裡觀眾會迷路」時才加一個淡入淡出。

**延伸 idea：** 拍一支「同一場景、三種轉場對比」的 60 秒短片，用攝影 Vlog 形式展示硬切、淡入、滑動的差異，順便教學。
