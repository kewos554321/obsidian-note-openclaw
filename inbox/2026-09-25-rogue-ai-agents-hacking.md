## 台灣房市快評（2026-09-25）

**1. 整體趨勢**
央行選擇性信用管制持續發酵，投資買盤退場，市場以自住與換屋剛需為主軸，成交量低檔盤整、價格呈現「蛋黃區撐盤、蛋白區鬆動」的兩極化格局。高總價物件去化慢，賣方讓利意願提高，議價空間明顯優於去年。

**2. 值得注意的地區／物件**
- **雙北蛋黃區**：大安、信義、松山捷運宅與學區宅仍具保值性，租賃需求穩定（如永春站、忠孝新生周邊）。
- **桃竹中壢、竹北**：竹北高鐵特區、中壢體育園區周邊新案供給大，投資客退場後可留意讓利案；竹北「國賓大悅」這類4房雙車稀有釋出，適合換屋族議價。
- **台中太平、高雄仁武**：低總價透天與首購三房為主力，順天璞月、仁武大地坪透天這類產品自住需求撐盤，但增值空間有限。
- **店面／透天**：樹林大安路店面、桃園慈文路整修透天，租金投報率約2～3%，適合長期收租型買方。

**3. 對自住者的建議**
- 善用賣方讓利期，蛋黃區中古屋議價空間約5～10%，蛋白區新案可談到10～15%。
- 優先選捷運、學區、生活機能成熟區，避開供給量大的重劃區邊緣。
- 貸款成數受限，自備款至少備3成，並預留裝修與持有成本。

**4. 對投資者的建議**
- 短線炒作已無空間，改採「長期收租＋都更危老」策略。
- 避開高總價、大坪數產品（如實價登錄破億物件），流動性差。
- 可關注雙北捷運周邊小宅、桃竹中壢低總價三房，租金投報率較佳。

**5. 風險提醒**
- 央行政策若再緊縮，蛋白區價格修正壓力加大。
- 高總價實價登錄案例（單價35～52萬/㎡）多為特殊產品，不宜作為區域行情基準。
- 留意2026下半年新案交屋潮，部分重劃區可能出現拋售。

#### 📚 Today's Concept: Short Interest and Days to Cover

What it is: Short interest is the total number of shares investors have borrowed and sold, betting the price will fall. Days to cover (short ratio) divides that short interest by the stock's average daily trading volume, estimating how many days shorts would need to buy back all those shares.

Why it matters: It gauges squeeze potential and sentiment. High short interest plus low days to cover signals crowded bearish positioning that can unwind violently if good news hits.

Example: A stock has 10 million shares shorted and averages 2 million shares traded daily. Days to cover = 10M / 2M = 5 days. If earnings surprise upward, shorts rush to buy back, but five days of normal volume is needed, so the price spikes hard as buyers outnumber sellers.

Rule of thumb: Days to cover above 5 with rising short interest is a squeeze warning; below 2 means shorts can exit quickly, so don't expect a sharp pop.

**連結:** https://leetcode.com/problems/reverse-linked-list/
> 📅 **Today's Daily Challenge:** #1188 Brace Expansion II [Hard] — Tags: Hash Table, String, Backtracking, Stack, Breadth-First Search, Sorting — https://leetcode.com/problems/brace-expansion-ii/

# 206. Reverse Linked List

**Problem Type:** Linked List — pointer manipulation (iterative + recursive)

**Key Insight:** You only need three pointers (`prev`, `curr`, `next`). Save `curr.next` before rewiring, then flip the arrow. The new head is `prev` when `curr` hits `None`.

**Approach (Iterative — preferred):**
1. Init `prev = None`, `curr = head`.
2. While `curr`: save `nxt = curr.next`, set `curr.next = prev`, advance `prev = curr`, `curr = nxt`.
3. Return `prev`.

**Python3 Solution:**
```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev, curr = None, head
        while curr:
            curr.next, prev, curr = prev, curr, curr.next
        return prev
```

**Complexity:** Time O(n) | Space O(1)

**Blind 100 Note:** Foundational linked-list problem — teaches pointer rewiring, the building block for Reverse Nodes in k-Group (25), Palindrome Linked List (234), Reorder List (143), and Reverse Linked List II (92). If you can't do this in your sleep, the harder variants will wreck you.

**Contest Tips:**
- **Tuple-swap trick:** `curr.next, prev, curr = prev, curr, curr.next` works because RHS is evaluated first — no temp variable needed. Fast to type under pressure.
- **Edge cases:** empty list (`head=None`) and single node both handled naturally — no special-casing needed.
- **Common mistake:** forgetting to save `curr.next` before overwriting it (classic infinite loop / lost tail).
- **Recursive version** is elegant but O(n) stack space — mention it in interviews, use iterative in contests.
- **Follow-up:** "Reverse in place" — this *is* in place; don't allocate new nodes.

#### 📷 Today's Concept: Post — Color Grading with HSL and Tone Curves

**What it is:** HSL (Hue, Saturation, Luminance) lets you adjust individual colors independently, while Tone Curves remap brightness and contrast across shadows, midtones, and highlights. Together they're the core of post-production color grading.

**Why it matters:** HSL isolates problem colors (skin, sky, foliage) without affecting the whole image, and Curves sculpts mood and contrast. This is how you get cinematic looks instead of flat, "edited" ones.

**How to apply it:**
1. Start with Curves: add a gentle S-curve (lift shadows slightly, pull highlights down) for filmic contrast.
2. Use the Curve's blue channel: lift shadows for cool shadows, lower highlights for warm skin — instant cinematic split-tone.
3. In HSL, target Orange/Red for skin: reduce saturation slightly, nudge luminance up for healthy tones.
4. For landscapes, boost Blue luminance and drop Blue saturation for richer skies; adjust Green hue toward yellow for natural foliage.
5. Grade video the same way in DaVinci Resolve or Premiere — match your photo look for consistency.

**Sony A7C tip:** Shoot S-Log2/S-Log3 (Picture Profile PP7/PP8) for video to preserve grading latitude. For stills, shoot RAW — HSL and Curves need that data. The compact body pairs well with the Sony 35mm f/1.8 for street and portrait work.

**Common mistake:** Over-saturating everything. Beginners push HSL globally, creating neon skin and radioactive grass. Fix: adjust one color at a time, and always check skin tones first — they anchor realism.

#### 📚 Today's Concept: Distributed Transactions and the Saga Pattern

**What it is:** A distributed transaction spans multiple services/databases that can't share a single ACID transaction. The Saga pattern replaces that with a sequence of local transactions, each paired with a compensating action to undo it if a later step fails.

**When to use it:** Use it when a business operation touches several services (orders, payments, inventory) and you need eventual consistency without distributed locks. E.g., an e-commerce checkout that reserves stock, charges a card, and creates a shipment.

**Example:**
```
1. createOrder()      -> compensate: cancelOrder()
2. reserveStock()     -> compensate: releaseStock()
3. chargePayment()    -> compensate: refundPayment()
4. shipOrder()
// If step 3 fails, run releaseStock() then cancelOrder().
```

**Gotcha:** Sagas give eventual consistency, not isolation. Intermediate states are visible to other transactions, so you must design compensations to be idempotent and handle "dirty reads" (e.g., a user seeing a reserved-but-unpaid order). Also, compensations aren't always possible—shipping a physical package can't be "un-shipped," only refunded.
