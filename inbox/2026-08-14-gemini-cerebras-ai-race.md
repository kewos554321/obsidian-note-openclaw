#### 📚 Today's Concept: Earnings Per Share (EPS)

What it is: Earnings Per Share is a company’s net profit divided by its number of outstanding shares. It tells you how much profit each share of stock “owns” over a given period, usually quarterly or annually.

Why it matters: It’s the core input for valuation—multiply EPS by a price-to-earnings ratio to get a target stock price. You also use it to track profitability growth over time, which drives stock prices.

Example: Suppose Acme Corp has net income of $10 million and 5 million shares outstanding. EPS = $10M / 5M = $2.00 per share. If last year’s EPS was $1.50, that’s a 33% growth rate. If the industry average P/E is 20, a fair price estimate is $2.00 × 20 = $40 per share.

Rule of thumb: Watch for EPS growth driven by share buybacks rather than actual profit growth—if net income is flat but shares shrink, EPS rises artificially. Always check net income trend alongside EPS to avoid being fooled by financial engineering.

## 199. Binary Tree Right Side View

**Problem Type:** BFS Level-Order Traversal / DFS with level tracking

**Key Insight:** The right side view is simply the **last node at each level** when traversing level-by-level. BFS naturally processes levels, so we just take the last node of each level.

**Approach:**
1. If root is None, return empty list
2. Initialize queue with root and empty result list
3. While queue is not empty:
   - Get current level size (`len(queue)`)
   - Loop through all nodes in this level
   - Pop left node, add children to queue
   - If it's the last node in this level (index == size-1), append to result
4. Return result

**Python3 Solution:**
```python
from collections import deque

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        
        result = []
        queue = deque([root])
        
        while queue:
            level_size = len(queue)
            for i in range(level_size):
                node = queue.popleft()
                # Last node in this level = rightmost visible
                if i == level_size - 1:
                    result.append(node.val)
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
        
        return result
```

**Complexity:** Time O(n) | Space O(w) where w = max width of tree (worst case O(n) for skewed tree)

**Blind 100 Note:** Represents the **level-order traversal** pattern. It's on the list because it tests understanding of BFS and how to extract level-specific information. Similar problems: Binary Tree Level Order Traversal (102), Binary Tree Zigzag Level Order Traversal (103), Populating Next Right Pointers (116).

**Contest Tips:**
- **Edge cases:** Empty tree, single node, left-skewed tree (only left children), complete binary tree
- **Python trick:** Use `deque` from collections for O(1) popleft() — never use list.pop(0) which is O(n)
- **Alternative DFS approach:** Track max depth seen so far, visit right child first — useful if you need to avoid BFS queue memory
- **Common mistake:** Forgetting to check `if not root` first
- **Memory optimization:** If tree is very wide, DFS with right-first traversal uses O(h) space instead of O(w)

#### 📷 Today's Concept: Video — Gimbal Operation: Pan, Tilt, Follow Modes

**What it is:** Gimbal operation is the physical control of a motorized stabilizer to move the camera smoothly through space. Pan rotates the camera horizontally, tilt moves it vertically, and follow modes dictate how the gimbal interprets your hand movements to create fluid, intentional motion.

**Why it matters:** These movements replace static shots with cinematic energy, guiding the viewer’s eye and adding production value. Proper mode selection prevents robotic, jerky footage and lets you execute complex moves—like orbiting a subject—with ease.

**How to apply it:**
1. **Set the gimbal to Pan-Follow mode** (yaw active, pitch locked) for walking shots—keep your wrist straight and let the gimbal absorb your steps.
2. **For a tilt reveal**, switch to Lock mode (all axes locked) and physically push the joystick up or down slowly, or tilt your wrist in Follow mode for a subtle arc.
3. **Use Pan mode** for tracking a moving subject: rotate your torso, not your arms, to keep the horizon level.
4. **Practice the “ninja walk”**—bend knees, glide heel-to-toe—while framing a fixed point to master smooth forward motion.
5. **Match mode to intent**: Follow for dynamic action, Lock for static compositions, and POV for immersive walking shots.

**Sony A7C tip:** Enable **SteadyShot** (Menu → Camera Settings 1 → SteadyShot → On) and set the lens’s Optical SteadyShot to *Active* if available—this adds a safety net for high-frequency jitter the gimbal misses.

**Common mistake:** Overcorrecting with your hands—gripping tight and fighting the gimbal. Relax your grip, let the motor do the work, and move your whole body as one unit.

#### 📚 Today's Concept: Rate Limiting Algorithms (Token Bucket, Leaky Bucket)

**What it is:** Rate limiting controls how often an action is performed within a time window. Token Bucket allows bursts by accumulating tokens (each request consumes one), while Leaky Bucket processes requests at a fixed, constant rate regardless of incoming spikes.

**When to use it:** Use Token Bucket for APIs where you want to permit short bursts (e.g., a user uploading 10 photos quickly) but cap sustained load. Use Leaky Bucket for downstream services that cannot handle bursts (e.g., a database write queue that must process exactly 100 ops/sec).

**Example (Token Bucket, pseudocode):**
```python
tokens = capacity  # e.g., 5
last_refill = now()
def allow():
    tokens = min(capacity, tokens + (now() - last_refill) * rate)
    if tokens >= 1:
        tokens -= 1
        return True
    return False
```

**Gotcha:** Don’t confuse the two. Token Bucket *allows* bursts (it drops excess tokens), while Leaky Bucket *forces* a fixed rate (it queues or drops excess). A common mistake is using Token Bucket for a system that must never exceed a hard limit—use Leaky Bucket or a fixed-window counter instead.
