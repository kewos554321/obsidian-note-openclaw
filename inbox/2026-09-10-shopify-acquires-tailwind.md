### 🏠 台灣房市
> `2026-09-10 09:18:00`

#### AI 分析
**1. 整體趨勢（2026年9月）**
央行第七波選擇性信用管制持續發酵，投資買盤明顯退場，市場由「賣方市場」轉向「買方市場」，成交量較去年同期萎縮約兩成。價格呈現「蛋黃區緩跌、蛋白區修正」格局，高總價物件議價空間擴大至10–15%，但首購剛需產品因貸款成數受限，買氣同樣保守。

**2. 值得注意的地區與物件**
- **高總價住宅（本次實登5筆均逾8,000萬）**：單價落在27–52萬/㎡，台北市精華區仍有支撐，但非核心區已見鬆動，去化天數拉長。
- **老舊華廈／大樓**：342.6㎡成交單價近52萬/㎡，顯示「地段＋都更潛力」仍是高資產族布局重點。
- **中南部蛋白區**：預售屋讓利、成屋降價求售案例增加，投資客拋售壓力浮現。

**3. 對自住者的建議**
- 善用買方市場優勢，優先鎖定**蛋黃區中古屋**，議價空間大且貸款條件較佳。
- 避開供給量大的重劃區，避免未來轉手競爭激烈。
- 自備款至少備足3成，因銀行鑑價趨嚴、成數普遍下修。

**4. 對投資者的建議**
- 短期炒作已無空間，**租金投報率**才是核心，建議聚焦捷運沿線、學區周邊的小坪數產品。
- 高總價物件流動性差，除非長期持有等都更，否則不宜追高。
- 保留現金、等待2027年政策鬆綁訊號再進場，會比現在搶進更穩健。

**5. 風險提醒**
若央行持續緊縮或經濟成長放緩，蛋白區房價可能再修正5–10%，投資者應嚴控槓桿，自住者則可視為「撿便宜」的窗口期。

#### 📚 Today's Concept: Price-to-Book (P/B) Ratio

What it is: The Price-to-Book ratio compares a company's stock price to its book value per share, which is total assets minus liabilities divided by shares outstanding. It tells you how much investors pay for each dollar of net accounting value.

Why it matters: It helps you spot companies trading below their liquidation value or flag overheated prices, especially in capital-heavy industries like banks and manufacturing where book value is meaningful.

Example: A bank has $50B assets, $45B liabilities, so book value is $5B. With 100M shares, book value per share is $50. If the stock trades at $40, P/B is 0.8, meaning you pay 80 cents per dollar of net assets. If it trades at $75, P/B is 1.5.

Rule of thumb: P/B below 1 can signal a bargain or a value trap, so always check why it's cheap; P/B is nearly useless for asset-light software firms where value comes from code and talent, not the balance sheet.

**連結:** https://leetcode.com/problems/invert-binary-tree/
> 📅 **Today's Daily Challenge:** #2347 Count Nodes Equal to Average of Subtree [Medium] — Tags: Tree, Depth-First Search, Binary Tree — https://leetcode.com/problems/count-nodes-equal-to-average-of-subtree/

# 226. Invert Binary Tree

**Problem Type:** Binary Tree DFS / Recursion (structural transformation)

**Key Insight:** Inverting a tree = swap left/right children at every node, then recurse. The swap is local; recursion handles the rest. This is the canonical "tree recursion" template.

**Approach:**
1. Base case: if `root is None`, return `None`.
2. Swap `root.left` and `root.right` (single tuple assignment).
3. Recurse on both children (now swapped).
4. Return `root`.

**Python3 Solution:**
```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if not root:
            return None
        root.left, root.right = self.invertTree(root.right), self.invertTree(root.left)
        return root
```

**Complexity:** Time O(n) | Space O(h) — h = tree height (O(log n) balanced, O(n) skewed). Recursion stack.

**Blind 100 Note:** This is the "hello world" of tree recursion — it teaches the **DFS post-order template** (recurse, then combine) that underpins nearly every tree problem: max depth, same tree, symmetric tree, diameter, LCA. Master the pattern here, reuse it everywhere. Practice next: 104 (Max Depth), 100 (Same Tree), 101 (Symmetric Tree), 543 (Diameter).

**Contest Tips:**
- **One-liner swap trick:** `root.left, root.right = self.invertTree(root.right), self.invertTree(root.left)` — Python evaluates RHS first, so no temp variable needed. This is the idiomatic contest form.
- **Edge cases:** empty tree (`None`), single node, skewed tree (watch recursion depth — fine for LeetCode's n ≤ 100).
- **Iterative alternative** (if recursion depth worries you): BFS with `deque`, swap children as you pop. Same O(n) time, O(w) space.
- **Common mistake:** swapping *values* instead of *pointers* — works for this problem but breaks on trees with duplicate values or when node identity matters. Always swap the child references.
- **Don't overthink:** no need to return anything from the recursive calls if you mutate in place — but returning `root` keeps the code composable and matches the signature.

#### 📷 Today's Concept: Color — Color Grading for Skin Tones

**What it is:** Color grading for skin tones is the process of adjusting hue, saturation, and luminance so skin looks natural and consistent across a shot. It's about protecting the skin's color while you stylize everything around it.

**Why it matters:** Viewers instantly notice bad skin — greenish, orange, or gray faces break immersion. Clean skin tones make footage look professional and cinematic, even with a simple grade.

**How to apply it:**
1. Set white balance first — get skin neutral before any creative grade.
2. Use a vectorscope: skin should sit along the "skin tone line" (roughly 11 o'clock), regardless of ethnicity.
3. Qualify skin with a mask or HSL keyer, then adjust hue/sat separately from the rest of the frame.
4. Grade the environment (teal shadows, warm highlights) *around* the protected skin.
5. Check on multiple screens — phone, monitor — before exporting.

#### 📚 Today's Concept: Consistent Hashing

**What it is:** A hashing technique that maps both servers and keys onto a circular hash ring, so adding or removing a node only remaps ~1/N of keys instead of nearly all of them. Each key is assigned to the first node clockwise from its hash position.

**When to use it:** Use it for distributed caches, sharded databases, or load balancers where nodes join/leave dynamically and you can't afford mass cache misses or data reshuffling. Example: Redis Cluster, Cassandra, and CDNs distributing content across edge servers.

**Example:**
```python
ring = sorted([hash(f"node{i}") for i in range(4)])
def get_node(key):
    h = hash(key)
    for pos in ring:
        if h <= pos: return pos
    return ring[0]  # wrap around
```

**Gotcha:** Without virtual nodes (each physical node hashed many times onto the ring), key distribution is uneven — one node can end up owning a huge arc. Always use 100+ vnodes per physical node to balance load.

#### 🎬 今日主題：旅遊 — 旅遊影片的 3 幕結構：期待 / 現場 / 反思
**類別：** 旅遊

**是什麼：** 把旅遊片分成「期待→現場→反思」三段，像故事一樣有起承轉合，而不是流水帳。期待鋪懸念，現場給體驗，反思留餘韻。

**為什麼重要：** 觀眾留下來是因為想知道「然後呢」。有結構的影片完播率高，也讓你剪輯時知道哪些素材該留、哪些該砍。

**怎麼做：**
1. **期待（15-20秒）**：出發前拍一句「我為什麼要去這裡」，用手機或 A7C 自拍都行。
2. **現場**：只留 3-5 個最有感的片段，每個片段開頭用一句旁白或字幕帶出重點。
3. **反思（結尾10秒）**：對著鏡頭說一句這趟旅程的感想，不用長，真誠就好。
4. 剪輯時先排這三段骨架，再補畫面，AI 工具（如 Descript、CapCut）幫你自動上字幕、去贅字。

**新手常犯的錯：** 把現場拍成流水帳，每餐每景都放。避免方法：每個片段問自己「這對故事有推進嗎？」沒有就刪。

**延伸 idea：** 拍一支「帶 A7C 去某個小鎮一日遊」，開頭說「我想測試這台相機在旅行中到底夠不夠用」，結尾給出三個優缺點——同時滿足旅遊與科技開箱。
